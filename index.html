Repository & Project Structure

S1One repo per project, not per person

The work survives the author leaving.

adamolab/                  # one GitHub org
├── reaction-time-study/   # one repo per project
├── eye-tracking-2026/
└── saccade-model/

S2Standard top-level layout

You find things without asking anyone.

saccade-model/
├── README.md
├── data/            # or a pointer to storage
├── src/
├── results/
└── environment.yml

S3No data committed to git

Git chokes on large binaries.

# .gitignore
data/
*.h5

# version data with DVC instead of git
dvc add data/raw.h5

S4README answers three questions

New members onboard without you.

# Saccade Model
**What:** fits saccade latency from eye-tracking data.
**Setup:** `conda env create -f environment.yml`
**Run:** `make all`

git init

# ...work, run tests...

Access outlives any one person.

# lab org remote, not a personal account
git remote add origin \
  git@github.com:adamolab/saccade-model.git

Environments & Reproducibility

E1Every project pins its environment

'Works on my machine' is not a result.

# environment.yml
name: saccade
dependencies:
  - python=3.11
  - numpy=1.26.4
  - pandas=2.2.1

E2One command reproduces the main result

Untested reproducibility is a guess.

all: results/fig1.pdf

results/fig1.pdf: src/plot.py data/clean.csv
	python src/plot.py

E3Set and record a random seed

Same input should give the same figure.

import numpy as np, torch
SEED = 42
np.random.seed(SEED)
torch.manual_seed(SEED)

E4Scripts or clean notebooks for published results

Out-of-order cells lie.

# run a notebook top-to-bottom, no manual state
jupyter nbconvert --to notebook --execute \
  --output out.ipynb analysis.ipynb

Coding Conventions

C1Auto-formatter per language

No human should format code.

black src/                          # Python
Rscript -e 'styler::style_dir("R")'  # R
shfmt -w scripts/                   # Shell

C2Descriptive names beat comments that explain bad names

A good name never goes stale.

# bad
srt = df[df.srt > 0.1]
# good
valid = trials[trials.reaction_time > 0.1]

C3No hard-coded absolute paths

/Users/alice/ breaks for everyone else.

# bad
df = pd.read_csv("/Users/alice/data/rt.csv")
# good
from pathlib import Path
DATA = Path(__file__).parent / "data"
df = pd.read_csv(DATA / "rt.csv")

C4Functions for anything used more than twice

Fix it once, not in five places.

def zscore(x):
    return (x - x.mean()) / x.std()

rt_z  = zscore(df.rt)
amp_z = zscore(df.amp)

C5Config at the top, not scattered

Changing a run should take one edit.

# config.py
RAW    = "data/raw.csv"
RT_MIN = 0.1
N_BOOT = 10_000

Naming Conventions

N1Python identifiers follow PEP 8

The linter and every reader expect it.

rt_min = 0.1                 # variable: snake_case
RT_MAX = 2.0                 # constant: UPPER_SNAKE
def clean_trials(raw): ...   # function: snake_case
class SaccadeModel: ...      # class: PascalCase

N2R identifiers follow the tidyverse style

A dot means an S3 method, so avoid dots.

rt_min <- 0.1                       # snake_case
clean_trials <- function(raw) { }   # snake_case
# avoid: clean.trials  (dot = S3 method)

N4Shell: snake_case locals, UPPER_SNAKE exported

Hyphens are illegal in shell variable names.

DATA_ROOT=/mnt/labshare      # exported: UPPER_SNAKE
clean_trials() {             # function: snake_case
  local raw_file="$1"        # local: snake_case
}

N5Constants and classes are cross-language

Keep the shouted categories recognizable.

UPPER_SNAKE_CASE   constants, env vars   (all languages)
PascalCase         classes, types        (all languages)

N6Filesystem names are lowercase

Data/ and data/ collide across machines.

mkdir raw-data        # good
mkdir Raw_Data        # collides on case-insensitive macOS

N7No spaces in names

Spaces force quoting and break scripts.

eye-tracking-data.csv     # good
eye tracking data.csv     # needs quoting everywhere

N8Restrict names to a-z 0-9 - _ .

Other characters are illegal or shell-special.

s01_congruent_v02.csv     # good
s01:congruent (2)!.csv    # illegal on Windows, shell-hostile

N9Avoid reserved names, keep paths short

Windows chokes on con, nul, and long paths.

reserved on Windows: con prn aux nul com1..com9 lpt1..lpt9
keep the full path under 260 characters

N10Repositories and branches use kebab-case

Matches GitHub, URLs, and the ecosystem.

adamolab/eye-tracking-2026         # repo
git switch -c fix-outlier-filter   # branch

N11Directories use kebab-case

Readable in a URL and a terminal.

saccade-model/
├── raw-data/
├── figure-scripts/
└── clean-output/

N12Script files follow language import rules

Python cannot import a hyphenated module.

data_cleaning.py     # Python module, importable
clean_data.R         # R script
run-analysis.sh      # shell tool, a CLI command

N14Config keys use snake_case

They map straight onto code variables.

# config.yml
rt_min: 0.1
n_boot: 10000
data_root: /mnt/labshare

Data Management

D2Consistent, sortable file naming

final_final2 is where projects die.

2026-07-08_s01_congruent_v02.csv
2026-07-08_s02_incongruent_v02.csv
# not:  final data (2)!!.csv

D3Every dataset has a data dictionary

Data without metadata turns to noise.

# data_dictionary.md
rt        Reaction time, seconds
accuracy  1 = correct, 0 = error
subject   Anonymized ID (s01..s40)

D53-2-1 backup for irreplaceable raw data

Irreplaceable means irreplaceable.

copy 1  /mnt/labshare/saccade     primary
copy 2  external HDD              weekly rsync
copy 3  institutional cloud      offsite

D7Sensitive data documented and access-controlled

Law and ethics require it.

python deidentify.py raw/ -o safe/
chmod 700 safe/            # owner-only access

Checking a repository

These rules are published as a plain-text file an agent can read whole: llms.txt. Ask for an audit, not a fix.

claude "Read https://adamo-lab.github.io/guidelines/llms.txt, then
audit this repository against every rule. For each rule ID give
PASS, FAIL, or N/A with the file or command that proves it.
Do not change any files."

Or keep a local copy so every session starts with the rules:

curl -o LAB-GUIDELINES.md https://adamo-lab.github.io/guidelines/llms.txt

In a chat window, paste llms.txt plus your repo tree, README, environment lock, and entry-point script. The file ends with a Not adopted list — those were vetoed and must not be reported as failures.

Layout, git history, pinned environments, naming, and hard-coded paths are checkable from the repository. Whether the D5 backup ran, who has access under D7, and whether the storage path in the README is still live are not — those stay a human check.

No rule matches that.
